# namportfolio 設計方針

アクティブ運用戦略の**事後的**パフォーマンス評価と可視化を行う Python パッケージ。

チーム内・自分用の**実験ツール**として使う。分析条件（分位数、ホライズン、ユニバース、期間）
は頻繁に変わるため、変わるものは引数で振れるようにし、構造は薄く保つ。

## 0. スコープ

**対象** — シグナル生成からポートフォリオ運用結果までの評価を、以下の流れでカバーする。

```
シグナル前処理・診断 → 分位分析 → 保有分析 → リターン評価 → 要因分解 → リスク検証 → 統計的頑健性
     (F1)              (F2)      (F3)      (F4)     (F5,F6)     (F7)        (F8)
```

**非対象**

- ポートフォリオ最適化（別パッケージ）
- バックテスト実行エンジン（約定・コストモデル）
- データ取得、リスクモデル生成（ファクターリターン推定は実装しない）
- コスト調整後リターン、流動性・キャパシティ、複数戦略比較、Excel / PDF 出力
- **将来の拡張に備えた抽象化**（§2.5）

## 1. 機能整理

★ = 当初要望の4機能

### F1. シグナル前処理・診断 (`signals.py`)

**入力**: シグナル値（パネル）、任意でグループ（業種等）・時価総額・エクスポージャー

| 機能 | 内容 |
|---|---|
| 前処理 | winsorize（分位／σ 基準）、z-score / rank 標準化、業種中立化、サイズ中立化 |
| カバレッジ診断 | 有効銘柄数の推移、欠損率、ユニバース被覆率、分布の歪度・尖度、外れ値検出 |
| シグナル間相関 | 複数シグナルの Pearson / Spearman 相関行列、相関の推移、冗長性チェック |
| **既存ファクター曝露** | シグナルの Barra スタイルファクターへの曝露＝**アルファの独自性** |

「このシグナルは結局モメンタムなのでは」に答える機能。曝露の計算は F6 を再利用する。

**図**: カバレッジ推移 / 分布ヒストグラム（前処理前後）/ 相関ヒートマップ / 曝露バー・時系列

---

### F2. 分位ポートフォリオ分析 ★ (`quantile.py`)

**入力**: シグナル値、フォワードリターン（1つ以上のホライズン）、任意でグループ・ウェイト

| 機能 | 内容 |
|---|---|
| 分位割当 | 全体分位 / グループ内中立分位、分位数 N 可変、同値の扱いを明示 |
| **クラス列でポート** | 分位を計算せず、データにあるラベル列（格付け・スタイル区分など）でポートを組む |
| **欠損クラス** | ファクター値が欠損している銘柄を別クラスとして集計（欠損がランダムでないときに効く） |
| 分位別リターン | 期間別・平均・累積・年率、標準誤差と t 値、単調性 |
| ロング・ショート | top−bottom スプレッド、累積、リスク調整後 |
| IC | Pearson / Spearman（Rank IC）、IC 時系列、平均・std・ICIR・t 値、グループ別 IC |
| ファクター減衰 | 複数ホライズンの IC / 分位リターン、シグナル自己相関 |
| 回転率 | 分位別ターンオーバー、分位遷移行列（`holdings` を利用） |

**「値が無い」と「分位を作れない」を区別する。** 前者（ファクター欠損）は欠損クラスに入れ、
後者（その日の銘柄数が `min_assets` 未満）は分位を付けずに除外する。混ぜると、ユニバースが
薄い日の銘柄が欠損クラスに紛れ込む。

**欠損クラスは順序を持たない。** 図では順序の濃淡に混ぜず中立色で描き、ロング・ショートの
端の選択からも除外する。

**図**: 分位別平均リターン棒 / 分位別累積リターン / IC 時系列＋移動平均 / IC ヒートマップ（年×月）/ 減衰カーブ / ターンオーバー推移

---

### F3. 保有ベース分析 (`holdings.py`)

**入力**: ポートフォリオウェイト、任意でベンチマークウェイト・銘柄リターン・銘柄属性

| 機能 | 内容 |
|---|---|
| 保有構造 | 銘柄数、集中度（上位N銘柄比率、HHI）、業種・サイズ・国配分、アクティブウェイト上位／下位 |
| ポートフォリオ特性 | 加重平均 PER / PBR / 配当利回り / 時価総額 / ROE の推移、ベンチ対比 |
| 寄与度分析 | 銘柄別・セクター別のリターン寄与（top / bottom contributors）、累積寄与 |
| 売買分析 | ターンオーバー（片道／両道、名前／ウェイトベース）、保有期間分布、新規／売却銘柄 |

寄与度分析は「先月なぜ勝った／負けたか」に最短で答える。ターンオーバーは本モジュールを正とし F2 が利用する。

**図**: 配分の積み上げ面 / 集中度推移 / 寄与度 top-bottom バー / 特性値の時系列 / ターンオーバー推移

---

### F4. ポートフォリオ・リターン評価 ★ (`performance.py`)

**入力**: リターン系列（任意でベンチマーク、無リスク金利）。またはウェイト＋銘柄リターンから合成。

| 区分 | 指標 |
|---|---|
| 絶対 | 累積リターン、CAGR、年率ボラ、シャープ、ソルティノ、カルマー、勝率、平均勝ち／負け、歪度・尖度、VaR / CVaR、ベスト／ワースト期間 |
| ドローダウン | 最大DD、上位N個の DD（開始・底・回復日、期間）、アンダーウォーター系列 |
| 相対 | アクティブリターン、トラッキングエラー、情報比、ベータ、ジェンセンα、相関、上昇／下落キャプチャ |
| 期間集計 | 月次・四半期・年次リターンテーブル |
| ローリング | リターン、ボラ、シャープ、ベータ、TE、IR、相関 |

**図**: 累積リターン（対数軸オプション）/ アンダーウォーター / 月次ヒートマップ / 年次バー / ローリング指標 / リターン分布

---

### F5. Brinson 帰属 ★ (`attribution.py`)

**入力**: ポートフォリオ／ベンチマークウェイト、セグメント別リターン、セグメント定義

| 機能 | 内容 |
|---|---|
| BHB | allocation = $(w_p - w_b) r_b$ / selection = $w_b (r_p - r_b)$ / interaction |
| BF | allocation = $(w_p - w_b)(r_b^{(i)} - r_b)$（ベンチ超過基準）、selection は BHB と同じ |
| 項数 | 3項（alloc / sel / interaction）または 2項（interaction を selection に統合） |
| 多期間リンキング | Carino / Menchero / GRAP / Frongello / 単純加算 |
| 多階層 | セクター → 業種など（オプション） |

**入力は 2 経路。** 銘柄レベル（ウェイト・リターン・銘柄→セグメント対応表）を集計する経路と、
セグメント集計済みを直接受け取る経路。前者を後者に変換して合流させる。

**図**: ウォーターフォール / セグメント別効果バー / 累積効果の時系列 / セグメント×時点ヒートマップ

---

### F6. Barra リスク分解 ★ (`risk.py`)

**入力**: エクスポージャー $X$、ファクター共分散 $F$、特異リスク $D$、ポート／ベンチウェイト

| 機能 | 内容 |
|---|---|
| エクスポージャー | ポート／ベンチ／アクティブのファクターエクスポージャー、時系列推移 |
| リスク分解 | トータルリスク $\sigma$、ファクターリスク、特異リスク |
| ファクター寄与 | MCTR（限界寄与）、CCTR（リスク寄与）、寄与率 |
| グループ集計 | スタイル／業種／国など factor group 単位 |
| リターン帰属 | 期間ごとのファクター寄与 $x_k f_k$・特異リターン・累積寄与 |
| 共分散の算出 | 社内ファクターリターン系列から $F$（サンプル／EWMA）と $D$ を組み立てる |

$$\sigma_p^2 = w^\top X F X^\top w + w^\top D w$$

**クロスセクション回帰によるファクターリターン推定は実装しない。** ファクターリターン・
エクスポージャー・スペシフィックリターンは社内リスクモデルから供給される前提。DataFrame を
そのまま受け取る（Protocol もモデルクラスも作らない）。

**図**: リスク寄与バー / エクスポージャー時系列・ヒートマップ / リスク分解の積み上げ面 / 累積ファクター寄与

---

### F7. リスクモデル妥当性検証 (`risk.py`)

**入力**: 予測リスク（F6 の出力）＋実現リターン

| 機能 | 内容 |
|---|---|
| 事前 vs 事後 | 予測 TE と実現 TE の時系列比較、比率の推移 |
| **bias statistic** | 標準化リターン $z_t = r_t / \sigma_{t-1}$ の分散が 1 に近いか。信頼区間つき |
| ローリング検証 | 期間別・レジーム別の bias statistic |
| ストレス／シナリオ | ヒストリカルシナリオの適用、ファクターショック時の損益 |

**図**: 予測 vs 実現 TE の重ね描き / bias statistic の推移＋信頼区間帯 / シナリオ損益バー

---

### F8. 統計的頑健性 (`stats.py`)

**入力**: リターン系列、IC 系列、分位リターン等（F2 / F4 の出力）

| 機能 | 内容 |
|---|---|
| 有意性検定 | t 検定、**Newey-West**（自己相関補正）、ブートストラップ信頼区間 |
| サブサンプル分析 | 期間分割（前半／後半、N分割）、ローリング窓での安定性 |
| レジーム別分析 | 強気／弱気、高ボラ／低ボラ、金利上昇／下降（外生的レジーム定義） |
| 多重検定補正 | Deflated Sharpe Ratio、試行回数を考慮した過剰適合評価 |

F2・F4 の t 値算出も本モジュールを使う。

**図**: サブサンプル別指標の比較バー / レジーム別リターン / ブートストラップ分布

## 2. 共通設計

### 2.1 入力データ規約 ✅ 実装済み

**主たる入力形式は long（tidy）形式。** 日付と銘柄 ID をカラムとして持つフラットな DataFrame。

```
   date        bid      factor   ret      sector
0  2024-01-31  JP1301   1.24     0.012    建設
1  2024-01-31  JP1332  -0.31    -0.003    水産
```

分析関数の入口で `core.panel.as_wide()` を呼べば、以降は入力形式を意識せず行列として扱える。

| 入力 | 処理 |
|---|---|
| `date` / `bid` カラムを持つ long（**主**） | `pivot` |
| `MultiIndex (date, bid)` の DataFrame / Series | `unstack` |
| `DatetimeIndex` を持つ wide | そのまま |

```python
w = npf.as_wide(df, "factor")  # 単一の値カラムのみ。複数は 2 回呼ぶ
long = npf.to_long(w, "factor")  # 逆変換
```

- 値カラムは候補が 1 つに定まるなら省略可
- 文字列日付は `to_datetime` で変換、日付昇順にソート
- `(date, bid)` 重複は `pivot` 前に検出して件数と実例つきで報告
- **wide 化で空くセルは埋めない**（ユニバース変動で穴が空くのは正常。扱いは分析ごとに異なる）
- 日付・銘柄の突き合わせは `DataFrame.align` で済むため専用関数は置かない

**カラム名**は `core.config` にグローバル既定を持ち、関数引数で個別に上書きできる。

```python
npf.set_columns(date="trade_date", id="barra_id")  # セッション開始時に一度
npf.as_wide(df, "factor", date_col="dt")  # 個別上書き
```

### 2.2 規約

- リターンは**単純リターン**をデフォルト。対数は明示的な変換関数経由
- 頻度は日付差の中央値から自動推定（`infer_periods_per_year`）、`periods_per_year` で上書き可
- 欠損は暗黙に補完しない。扱いは呼び出し側が決める

### 2.3 API の形

**計算は純粋関数、戻り値は素の DataFrame / Series。**

```python
import namportfolio as npf

q = npf.quantile_returns(df, factor="value", fwd_ret="ret_20d", n=5)
ic = npf.rank_ic(df, factor="value", fwd_ret="ret_20d")

npf.plot_quantile_cumulative(q)  # Figure を返す（show() はしない）
```

複数の DataFrame をまとめて返す機能（分位分析の mean / ic / turnover など）だけ、
**基底クラスなしの素の dataclass** を返す。`summary()` の実装義務は課さない。

### 2.4 可視化 ✅ 基盤実装済み

- **matplotlib のみ。** 全関数は Figure を返し `show()` はしない。`ax` を渡せば
  既存の Axes に描く（複数図の組み合わせ用）
- 色・レイアウトは `viz/theme.py` に集約。`npf.viz` は遅延 import なので、
  matplotlib が無い環境でも `import namportfolio` は成功する
- plotly が必要になったら `viz/plotly_.py` を足す。既存コードは壊れない

**配色は用途で決まる。手で選ばない。**

| 役割 | 使いどころ | 構造 |
|---|---|---|
| categorical | 識別（複数戦略、ポート vs ベンチ） | 8 色を固定順に。循環させない |
| ordinal | 順序（分位 Q1..Q5） | 単一色相の濃淡。順序が色に出る |
| sequential | 量（連続値） | 単一色相 light→dark |
| diverging | 極性（正負のリターン） | 2 色相＋グレー中点 |

**分位を categorical で塗らない。** Q1〜Q5 には順序があるので ordinal を使う。

配色は色覚特性（P型・D型）下での識別性を検証済み（categorical の隣接ペア CVD ΔE 9.1 /
通常視 19.6、OKLab ×100）。色を差し替えるときは同じ検証を通す。

その他の描画ルール:

- **識別色は 8 系列まで。** 9 色目を作ると色覚特性下で既存色と区別できないため、
  上位のみ表示して残りを「その他」にまとめるか図を分ける（実装はエラーにする）
- **縦軸を 2 本にしない。** 尺度の違う 2 指標は図を分ける。重ねると読み手が
  ありもしない相関を見る
- 系列が 4 本以下なら凡例に加えて線の右端に直接ラベルを置く
- グリッドは実線のヘアライン（破線は「閾値」に見える）、上・右の枠線は消す
- マークを枠線で区切らず、背景色の隙間で分ける
- 全データ点に数値を書かない（ヒートマップのセルは数表を兼ねるので例外）
- ダークモードは `theme.set_mode("dark")`。明度を反転しただけの自動変換ではなく、
  暗い背景用に選び直した色を持つ
- 日本語ラベルを使う場合は `theme.use_japanese_font()` を呼ぶ（既定フォントに
  日本語グリフが無く豆腐になるため）

### 2.5 作らないもの

「後から足しにくいものだけ今決め、後から足せるものは作らない」。以下はすべて後者。

| 作らないもの | 理由 |
|---|---|
| `PlotBackend` ABC（matplotlib / plotly 抽象化） | 図 30〜40 個 × 2 実装の維持コストを、使うか分からない段階で背負わない |
| `AnalysisResult` ABC | `summary()` の実装義務が実験の邪魔になる。DataFrame をそのまま返す |
| `RiskModelLike` Protocol | DataFrame を直接受け取れば足りる |
| 例外の細分化 | `NamPortfolioError` と `ValidationError`（`ValueError` 継承）の 2 つのみ |
| `on_error` による raise/warn/ignore 切替 | 分岐とテストが増えるだけ。壊れる検証は raise、それ以外は検証しない |
| ウェイト合計チェック | 実験中に警告が出続けるのは邪魔 |
| 前処理の Transformer / Pipeline | 順序をパラメータとして振る要件が出るまで関数で足りる |

### 2.6 依存関係

| 区分 | パッケージ | 用途 |
|---|---|---|
| 必須 | pandas, numpy | 全計算 |
| optional `viz` | matplotlib | 描画 |
| optional `stats` | statsmodels, scikit-learn | 検定の補助（Newey-West の厳密版等） |

**全計算を pandas / numpy で完結させる。** Newey-West、ブートストラップ、EWMA 共分散、
中立化回帰はいずれも自前実装する。社内の制限環境で確実に動くことを優先する。

## 5. 決定事項

| 項目 | 決定 |
|---|---|
| 入力形式 | long（`date` / `bid` カラム）を主軸。MultiIndex・wide もアダプタで受ける |
| wide 変換 | 単一の値カラムのみ。複数値は 2 回呼ぶ |
| Barra リスクモデル | 社内提供のファクターリターン・エクスポージャー・スペシフィックリターンを DataFrame で受け取る。推定は実装しない |
| Brinson 入力粒度 | 銘柄レベルとセグメント集計済みの両方（前者を変換して合流） |
| 描画 | **matplotlib のみ。** plotly は必要になってから足す |
| 抽象化 | ABC / Protocol は作らない（§2.5） |
| 結果の型 | 素の DataFrame。複数返す場合のみ基底クラスなしの dataclass |
| モジュール分割 | 機能ごとに 1 ファイル。肥大化したら後で分割 |

## 6. 実装フェーズで確定する事項

- 各機能の詳細な入力シグネチャ（必須カラム、複数ホライズンの持ち方、ウェイトの受け渡し）
- リスク分解の $F$ を社内から直接受け取れるのか、ファクターリターン系列から算出するのか
- レジーム定義の与え方（外生ラベルのみか、リターンからの自動判定も提供するか）
